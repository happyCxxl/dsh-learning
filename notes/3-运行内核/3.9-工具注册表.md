## 0. 怎么读这一课

### 0.1 这一课是什么、不是什么

**是**：工具子系统的**一份定义、两个下游形态、一个解析器**——`defineTool` 的 schema DSL 怎么编译、`ctx.tools.register()` 怎么落地、`native`/`ptc`/`both` 三模式怎么改变模型看到的东西、限制（restriction）与作用域化注册怎么合成同一份"可见工具表"。
**不是**：工具执行流水线的逐个把关点（那是 `3.10`）、并发调度（`3.11`）、具体某个工具的业务逻辑。

### 0.2 现在只要记住 5 件事

1. **作者只写一份 schema**（`defineTool({ parameters, output: { schema, render } })`），注册表把它编译成两种下游形态：给模型的 `ToolSchema`、给执行器的校验器。
2. **注册 = `ctx.tools.register(definition)`，注册是副作用**：dispose 插件 fiber 即注销，返回值就是那个精确 disposer。
3. **`register()` 借用你的定义对象**（不深拷贝）：注册后改 schema 或换回调**不受支持**；要热替换就 dispose 再注册。
4. **入参硬校验、输出硬校验、展示软校验**：三条路径的失败行为不同（抛 `ToolArgsError` / 抛 `ToolOutputError` / 退回 `undefined`）。
5. **"谁能看见"与"谁能执行"由同一个解析器算一次**——所以不存在"提示词里没有、却能调"的缝。

### 0.3 明确授权：这些现在不用管

- `ptc` 模式里 `run_code` 程序怎么写、SDK 文本长什么样（`packages/core/tools/src/ptc.ts` / `ts-types.ts` / `py-types.ts`）——**第一次读不必进去**，只需知道"`ptc` 下模型只能直呼 `run_code`"；
- cordis 的 `Service` / `ScopedLayers` / `AnonymousEntries` 内部（那是第二编 `2.1`/`2.5`）；本文只在**用到**它们的地方点一句"它做什么"；
- 具体的工具实现（`packages/fs/tool-fs/src/read.ts` 全文、`tool-bash`、MCP 工具）——本文只摘其中与"声明形态"有关的一段。

### 0.4 本课依赖前面几课的词汇

`ctx` / `service` / `plugin` / `entry` / `layer` 由 `notes/1-结构与装配/1.1-名词与分层.md` 定义；`effect`（可逆副作用）与 `scope`（作用域）由第二编定义。本课**不重新解释**，必要时才加一句"它做什么"。

## 1. 最小词汇表（本课新增的 10 个词）

| 词 | 大白话 | 在源码里的样子 |
|---|---|---|
| **tool 工具** | 一段"模型可以点名调用"的能力，自带说明书（名字 / 描述 / 入参 schema） | `ToolDefinition` |
| **schema DSL** | 作者写 schema 用的那套精简写法（九种取值 + 四个纯注解） | `ValueSchemaSpec` / `ParameterSchemaSpec` |
| **`parameters`** | **入参**的 DSL。它本身是一张"属性表"，被当成一个**隐式开放对象**的根 | `parameters: { file_path: { type: 'string', required: true } }` |
| **`output.schema`** | **输出**的 DSL。根可以是对象 / 数组 / 标量 / null | `output: { schema: { type: 'string' }, render }` |
| **`render`** | 把"校验过的输出值"渲染成模型看到的内容块 | `render(args, value) => ContentBlock[]` |
| **硬校验 / 软校验** | 硬校验失败就抛错；软校验失败就**安静退回 `undefined`** | `ToolArgsError` vs `presentCall → undefined` |
| **pre-restriction 名字集合** | **过滤前**的全量工具名，只用于校验配置里写没写错名字 | `knownNames` |
| **限制 restriction** | 给某个 scope 的"全局工具"加一张 mask（`allow` 只留 / `deny` 去掉） | `ctx.tools.restrict({ allow, deny })` |
| **呈现模式 presentation mode** | 模型看到哪种形态：普通 schema / 只有 `run_code` / 两者都发 | `native` / `ptc` / `both` |
| **守卫 guard** | 在策略之后、执行之前的**单调拒绝**：只能拒，不能放行 | `ctx.tools.guard(fn)` |

> ⚠️ 上表 10 个词里，`restriction` 与 `guard` 的**完整语义**在 `3.10`（流水线把关）展开；本课只讲它们在注册表侧怎么存、怎么被同一个解析器用到。

## 2. 先建立画面

### 2.1 注册表站在哪（静态结构）

```
                    ┌──────────────────────────────────────────┐
   作者（工具插件）  │  defineTool({ name, description,         │
                    │    parameters, output:{schema,render},   │
                    │    execute, presentCall?, … })           │
                    └───────────────────┬──────────────────────┘
                                        │ 调用时立刻编译（无惰性）
                                        ▼
                    ┌──────────────────────────────────────────┐
                    │ defineTool 返回一个 ToolDefinition        │
                    │  · parameters  = 原始 JSON Schema（入参） │
                    │  · output.schema = 原始 JSON Schema（出参）│
                    │  · execute 已被包上 validate()            │
                    └───────────────────┬──────────────────────┘
                                        │ ctx.tools.register(def)（副作用）
              ┌─────────────────────────┴──────────────────────────┐
              ▼                       ▼                            ▼
    ① 按 scope 分层存放        ② 系统提示词 provider         ③ 执行解析
    ToolLayer.tools            wireSchemas(scope)            resolveExecution()
    （NamedEntries）           → ToolProviderResult          → 同一个 view()
              │                       │                            │
              └───────────────┬───────┴────────────────────────────┘
                              ▼
                   view(scope)：一次遍历算出
                   visible / knownNames / restrictableNames
```

一句话：**上面一个入口（`register`），下面三个消费者（提示词、查找、执行），中间一张表（`view`）。**

### 2.2 一次调用穿过哪里（动态过程）

```
模型说"我要用 read"
   │
   ▼
resolveExecution(name, scope, nested)      ← 先 get()（含 view），再过 collapses()
   │  · 不在 visible 里          → undefined（后续报 UNKNOWN_TOOL）
   │  · 在 visible 里但被 ptc 折叠 → undefined（同一个 UNKNOWN_TOOL，但带"出路"文案）
   ▼
createExecution()：参数物化成无损 JSON + deepFreeze；守卫/策略都在它之后
   │
   ▼
tools/pre-execute  ──► 已注册的单调守卫 ──► tools/execute ──► tools/post-execute
   │                                                              │
   ▼                                                              ▼
定义自带 finalizeContent ──► 只观测的 tools/result（冻结后的最终结果）
```

> 严格说 `createExecution` 里**先做折叠早判**，再物化参数——它决定"这次调用要不要继续往下走"。逐节点的把关条件见 `3.10` 与 `docs/tool-execution-pipeline.zh.md`。

### 2.3 大白话版：作者写下 `defineTool` 之后，机器里发生了什么

**完全不用上面的术语**，先建立画面（来源：`docs/cookbook/adding-a-tool.zh.md` 第 7–38 行「最小形态」示例 + 本课读到的源码顺序）。

1. 作者写下一个对象：叫什么名字、干什么用、要哪些入参、成功时返回一个什么样的 JSON 值、这个值怎么变成给人看的文字。
2. 这个对象**当场**被翻译成两份通用的 JSON Schema（一份管入参、一份管出参）；翻译不合格（比如对象忘了写明"允不允许额外键"）**当场就报错**，不是等到第一次调用。
3. 作者把这个对象交给"登记处"：`ctx.tools.register(对象)`。登记处做几个前置检查（有没有输出声明、超时值合不合法、名字是不是保留名），然后把它**塞进当前作用域的那一层**。
4. "塞进去"这件事本身是一个**可撤销的副作用**：谁调用 `register` 就登记在谁那一层；那一层被销毁时它自动消失。
5. 与此同时，"说明书"会被投影成只有名字 / 描述 / 入参 schema 的**瘦身版**，交给系统提示词组装的提供者；**出参 schema、执行函数、展示回调都不会上线**。
6. 后来模型点名要调这个名字时，登记处**用同一张表**判断这个作用域到底能不能看见它、能不能执行它，然后才进入策略与执行。
7. 如果部署选了"只给模型一个代码执行工具"的模式，那么模型**直呼**别的名字会在策略之前就被判为"未知工具"，并被告知"请从代码程序里面调它"。

## 3. 结论先行

工具子系统的全部行为可以从一句话展开：**作者只写一份「统一的 schema DSL」，注册表把它编译成两种下游形态——给模型的 `ToolSchema` 和给执行器的校验器——并且「谁能看见」与「谁能执行」由同一个解析器算一次。**

| 结论 | 载体 | 出处 |
|---|---|---|
| 注册表是 `ctx.tools`，一个 Cordis Service；插件 `apply()` 里 `ctx.tools.register()` 即注册完毕，schema 自动流入系统提示词组装 | `ToolRuntime extends Service` | packages/core/tools/src/index.ts 第 807–813 行；同一文件第 854 行把 provider 挂到 `ctx.systemPrompt.tools()` |
| 注册有副作用边界：dispose 插件 fiber 即注销，`register()` 返回的就是那个精确 disposer | `layers.effect(...)` | packages/core/tools/src/index.ts 第 1083–1087 行 |
| schema 有两个方向：**入参**用隐式开放对象 DSL，**输出**用任意 JSON 根 DSL；两者在 `defineTool()` 调用时立刻编译成受强制执行的原始 JSON Schema 子集 | `defineTool` 第 577–578 行 | packages/core/tools/src/schema.ts 第 554–632 行 |
| 参数校验在 `execute` 主体之前发生，违规抛出 `ToolArgsError`（code `INVALID_ARGS`）；而**展示回调**（`presentCall`/`presentResult`）对同一参数做软校验，不合法就退回 `undefined`（通用卡片） | 硬校验第 597–601 行，软校验第 613–624 行 | packages/core/tools/src/schema.ts 第 460–480、554–632 行 |
| 呈现模式 `native` / `ptc` / `both` 决定**模型看到什么**，且是**按 agent（scope）** 解析的：deployment 默认 + preset/agent 自己声明的 `presentAs` | `modeFor()` | packages/core/tools/src/index.ts 第 922–933 行 |
| `ptc` 不只是「少发 schema」：它还折叠**可调用面**——模型直呼非 `run_code` 的名字在策略流水线之前就被判 `UNKNOWN_TOOL` | `collapses()` | packages/core/tools/src/index.ts 第 1351–1353 行，执行路径第 1407–1473 行 |
| 作用域化注册「遮蔽而不合并」：同名工具在更近的 scope 注册会盖住全局的那个；`restrict()` 只筛**继承来的**工具，绝不筛本 scope 自己注册的 | `view()` | packages/core/tools/src/index.ts 第 1178–1219 行（注释第 1156–1174 行讲透了「为什么自己的不算」） |
| 多重限制**取交集**；限制在 dispose 时解除；限制同时决定 schema 可见性与可执行查找（一个解析器，不存在「提示词里没有但能调」的缝） | `restrict()` / `admits()` | packages/core/tools/src/index.ts 第 757–764、1097–1124 行 |

一句话风险提示：`register()` **借用**你的定义对象（不做深拷贝），注册后再改 schema 或换回调不受支持——要热替换就 dispose 再注册（docs/cookbook/adding-a-tool.zh.md 第 43 行）。

> 本章共 14 块源码。每块上方标 `文件路径 第 A–B 行`，块后按「做什么 / 与哪个知识点相关 / 为什么这么写」讲解。凡有省略都在块内用注释写明省了哪些行、为什么省。

### 4.1 声明：`defineTool` 在调用时就把 DSL 编译掉

`DefineToolOptions` 的形状是「名字 + 描述 + `parameters`（属性表）+ `output:{schema,render,presentationMeta?}` + `execute` + 可选 `presentCall`/`presentResult`/`isConcurrencySafe`/`projectContent`/`finalizeContent`/`timeoutMs`/`deferLoading`」（packages/core/tools/src/schema.ts 第 483–545 行）。

#### 块 1｜DSL 的最高一层：三种根、九种取值

`packages/core/tools/src/schema.ts` 第 64–106 行

```ts
/**
 * Explicit object value schema. Openness is mandatory so a nested or output
 * object never acquires an accidental JSON Schema default.
 */
export interface ObjectValueSchemaSpec extends ValueSchemaAnnotations {
  type: 'object'
  properties?: ParameterSchemaSpec        // ← 显式对象的属性表：复用入参那张表
  additionalProperties: boolean           // ← 必填！不是可选
}

/** Author-only unconstrained lossless JSON node. */
export interface JsonValueSchemaSpec extends ValueSchemaAnnotations {
  type: 'json'                            // ← 只有作者能写的取值，编译成"空注解"schema
}

/** Exact-one union schema; at least two branches are required. */
export interface OneOfValueSchemaSpec extends ValueSchemaAnnotations {
  oneOf: readonly [ValueSchemaSpec, ValueSchemaSpec, ...ValueSchemaSpec[]]   // ← 元组类型：至少两支
}

/** One author-facing schema for any lossless JSON value root. */
export type ValueSchemaSpec =
  | StringValueSchemaSpec
  | NumberValueSchemaSpec
  | IntegerValueSchemaSpec
  | BooleanValueSchemaSpec
  | NullValueSchemaSpec
  | ArrayValueSchemaSpec
  | ObjectValueSchemaSpec
  | JsonValueSchemaSpec
  | OneOfValueSchemaSpec

/** One implicit parameter-root property, optionally required. */
export type ParameterPropertySpec = ValueSchemaSpec & { required?: true }

/**
 * Tool parameter schema. The map itself is an implicit open object root;
 * requiredness remains a per-property `required: true` annotation.
 */
export type ParameterSchemaSpec = {
  [key: string]: ParameterPropertySpec
  [key: symbol]: never                    // ← 符号键被类型层挡掉（运行期还会再拒一次）
}
// …（第 107–130 行：ParameterJsonSchema、Simplify、RequiredKeys、InferProperties 等类型级工具，
//   它们是 InferArgs 的实现细节，与本块"三种根"的知识点无关，此处省略）
```

按块讲解：

- **做什么**：把"作者能写什么"定死成**九种取值**（`string` / `number` / `integer` / `boolean` / `null` / `array` / `object` / 仅作者的 `json` / `oneOf`）与**四个纯注解**（`description` / `title` / `default` / `examples`，见第 12–21 行）。
- **与哪个知识点相关**：`parameters` 与 `output.schema` **共用同一套取值**，区别只在**根**——入参的根是一张**隐式开放**的属性表，输出可以是对象 / 数组 / 标量 / null 中的任意一种。这就是"一份 DSL、两个方向"。
- **为什么这么写**：`additionalProperties: boolean` 在 `ObjectValueSchemaSpec` 上是**必填**。作者原文（第 64–67 行）：「Openness is mandatory so a nested or output object never acquires an accidental JSON Schema default.」——JSON Schema 自己规定对象默认是开放的；如果 DSL 允许省略，作者就可能"以为写了封闭对象、其实开放"，所以这里干脆不给默认值，漏写就是编译期错误（块 4 的实测会看到这条报错）。

#### 块 2｜`defineTool`：编译、包校验、软校验展示

`packages/core/tools/src/schema.ts` 第 554–632 行

```ts
export function defineTool<const S extends ParameterSchemaSpec, const O extends ValueSchemaSpec>(
  options: DefineToolOptions<S, O>,
): ToolDefinition {
  // Object-literal methods do not use `this`; retaining references is safe.
  // …（第 557–573 行：把 options 上的 9 个回调各摘出一个局部常量，并配 oxlint 行内豁免；
  //   这一步与"绑定 this"有关，是风格处理，与本知识点无关，此处只留结论：下面用的是这些局部常量）
  const userExecute = options.execute
  const userRender = options.output.render
  // …
  if (options.timeoutMs !== undefined && (!Number.isFinite(options.timeoutMs) || options.timeoutMs <= 0)) {
    throw new Error(`defineTool(${options.name}): timeoutMs must be a positive finite number`)
  }
  const parameters = parameterSchemaSpecToJsonSchema(options.parameters)     // ① 入参：隐式开放对象根
  const outputSchema = valueSchemaSpecToJsonSchema(options.output.schema)   // ② 出参：任意 JSON 根
  const validate = (args: unknown): string[] => validateJsonSchemaValue(parameters, args, '')
  const tool: ToolDefinition = {
    name: options.name,
    description: options.description,
    parameters: parameters as unknown as Record<string, unknown>,
    output: {
      schema: outputSchema,
      render(args: unknown, value: JsonValue): ContentBlock[] {
        return userRender(args as InferArgs<S>, value as InferValue<NoInfer<O>>)
      },
      // …（第 589–593 行：presentationMeta 存在才挂上去；作用是"同一值 → 可回放的 UI 数据"，
      //   属于 UI 线，与本块"编译时机"无关）
    },
    // …（第 595–596 行：deferLoading / timeoutMs 存在才透传，两个条件展开，省略）
    async execute(args: unknown, exec: ToolRunContext): Promise<JsonValue> {
      const violations = validate(args)                      // ③ 硬校验：在用户主体之前
      if (violations.length > 0) throw new ToolArgsError(violations)
      return userExecute(args as InferArgs<S>, exec) as Promise<JsonValue>
    },
  }
  // …（第 603–608 行：projectContent / finalizeContent 存在才挂上去，纯透传包装，省略）
  // Presentation is display-only and may run on REPLAY of arbitrary logged args
  // (possibly from an older schema), so it must never throw: validate softly and
  // fall back to `undefined` (a generic UI presentation) on any mismatch, rather
  // than the hard `ToolArgsError` the execute path raises.
  if (userPresentCall) {
    tool.presentCall = (args: unknown): ToolCallView | undefined => {
      if (validate(args).length > 0) return undefined          // ④ 软校验：不抛，退 undefined
      return userPresentCall(args as InferArgs<S>)
    }
  }
  // …（第 619–624 行：presentResult 用同一句软校验，省略）
  if (userIsConcurrencySafe) {
    tool.isConcurrencySafe = (args: unknown): boolean => {
      if (validate(args).length > 0) return false               // ⑤ 软校验：不合法退化为"独占"
      return userIsConcurrencySafe(args as InferArgs<S>)
    }
  }
  return tool
}
```

按块讲解：

- **做什么**：`defineTool` 里**没有任何惰性求值**——①②两行在函数体前段就把两份 schema 编译完；③把硬校验包进 `execute`；④⑤把软校验包进展示回调与并发分类器。
- **依赖的变量从哪来**：`options` 就是作者传进来的那个对象字面量；`parameters` / `outputSchema` 是 ① ② 的产物（原始 JSON Schema）；`validate` 是闭包在 `parameters` 上的一个函数，**不需要每次重新编译 schema**。
- **与哪个知识点相关**：这是「声明即编译」与「入参硬校验 / 展示软校验」两条结论的同一处落点。注意 ③ 的报错类型是 `ToolArgsError`（code `INVALID_ARGS`），而 ④⑤ 只是 `undefined` / `false`——**同一个 `validate`，两种对待方式**。
- **为什么软校验**：作者原文（第 609–612 行）给出的理由是**回放**：「may run on REPLAY of arbitrary logged args (possibly from an older schema), so it must never throw」——会话日志回放时会拿**历史参数**去算卡片，旧 schema 的参数在新代码下可能不合法，展示路径绝不能因此崩掉。
- **为什么硬校验放在 `execute` 内部而不是注册表里**：因为**原始 JSON Schema 工具**（不走 `defineTool`、直接 `register` 一个自带 `parameters` 的定义）自行负责输入校验；把校验绑在 `defineTool` 产出的 `execute` 上，既保证了类型化工具的契约，又不把"必须校验"强加给所有注册者（docs/cookbook/adding-a-tool.zh.md 第 42 行末尾一句）。

- **为什么要有上限**：TypeScript 的类型实例化是编译期递归，深度不设限会让深层 schema 的 `tsc` 变慢甚至挂掉；用"数长度到 16 就加宽"换来**确定的编译成本**。运行时侧不需要这个上限（块 3 的显式任务栈管的是运行期栈安全）。

### 4.2 注册：`register()` 的五个前置检查与一个效应边界

#### 块 6｜`register()` 全文

```ts
  /**
   * Register globally or in the calling agent scope. Scoped tools shadow
   * globals; duplicates within one layer and the reserved `run_code` name fail.
   * @param definition - tool schema, execution, and optional finalization/presentation callbacks.
   * @returns the exact disposer that unregisters the tool.
   */
  register(definition: ToolDefinition): () => void {
    const name = definition.name
    const output = (definition as Partial<ToolDefinition>).output
    if (output === undefined || typeof output !== 'object'
      || typeof output.render !== 'function'
      || (output.presentationMeta !== undefined && typeof output.presentationMeta !== 'function')) {
      throw new TypeError(`tool "${name}" must declare output { schema, render, presentationMeta? }`)
    }
    assertSupportedJsonSchema(output.schema)                       // ① 出参 schema 必须落在受支持子集内
    const timeoutMs = definition.timeoutMs
    if (timeoutMs !== undefined
      && (!Number.isFinite(timeoutMs) || timeoutMs <= 0)) {
      throw new TypeError(`tool "${name}" timeoutMs must be a positive finite number`)   // ②
    }
    // Reserved unconditionally: any agent may select a code mode for itself,
    // so a name free to take under the deployment default would become a
    // collision the moment a preset mounted.
    if (name === RUN_CODE_NAME) {
      throw new Error(`tool name "${RUN_CODE_NAME}" is reserved for the PTC mode presentation transport and cannot be registered or shadowed`)   // ③
    }
    return this.layers.effect(                                     // ④ 效应边界：返回值就是 disposer
      this.ctx,
      layer => layer.tools.insert(name, definition),
      { label: 'tools.register()' },
    )
  }
```

- **做什么**：5 个前置检查（`output` 存在且 `render` 是函数、`presentationMeta` 若是给了也必须是函数、出参 schema 合法、`timeoutMs` 为正有限数、名字不是保留名），然后 `layers.effect` 插入。

```ts
/**
 * Apply configured tool order, inserting unlisted tools lexicographically at
 * {@link TOOL_ORDER_REST}. Unknown configured names fail; known but restricted
 * names may be absent.
 */
function orderTools(tools: ToolSchema[], toolOrder: string[] | undefined, knownNames: ReadonlySet<string>): ToolSchema[] {
  const reserved = tools.find(tool => tool.name === TOOL_ORDER_REST)
  if (reserved !== undefined) {
    throw new Error(`tool provider returned reserved tool name "${TOOL_ORDER_REST}" (reserved for toolOrder's rest entry)`)
  }
  if (toolOrder === undefined) return tools.sort(compareToolNames)
  const unknown = toolOrder.filter(name => name !== TOOL_ORDER_REST && !knownNames.has(name))   // ← 校验用的是 knownNames
  if (unknown.length > 0) {
    throw new Error(`toolOrder lists unregistered tool${unknown.length > 1 ? 's' : ''} ${unknown.map(name => `"${name}"`).join(', ')}; known tools: ${[...knownNames].sort().join(', ') || '(none)'}`)
  }
  const listed = new Set(toolOrder)
  const rest = tools.filter(tool => !listed.has(tool.name)).sort(compareToolNames)
  return toolOrder.flatMap(name =>
    name === TOOL_ORDER_REST ? rest : tools.filter(tool => tool.name === name))
}
```

```ts
  schemas(scope?: ScopeKey): ToolSchema[] {
    return [...this.view(scope).visible.values()].map(definition => this.schemaOf(definition, true))   // ← true = 深克隆
  }

  /** Project visible callable tools onto the generated PTC mode SDK contract. */
  private sdkSchemas(scope?: ScopeKey): ToolSdkSchema[] {
    return [...this.view(scope).visible.values()]
      .filter(definition => definition.name !== RUN_CODE_NAME)               // ← SDK 不列 run_code 自己
      .map((definition): ToolSdkSchema => {
        const output = snapshotJsonValue(definition.output.schema)           // ← SDK 额外带上出参 schema
        // …（第 1270–1273 行：快照失败的分支带 v8 覆盖率豁免注释——注册时已验过，这里只是防御，省略）
        return {
          ...this.schemaOf(definition, true),
          output,
        }
      })
  }

  /** Project one definition onto the model-facing schema fields. */
  private schemaOf(definition: ToolDefinition, detachParameters: boolean): ToolSchema {
    const { name, description, parameters, deferLoading } = definition       // ← 只解构出这四个
    const detached = detachParameters ? snapshotJsonValue(parameters) : parameters
    if (detached === undefined) {
      throw new Error(`tool "${name}" parameters must be lossless JSON before schema projection`)
    }
    return {
      name,
      description,
      parameters: detached,
      ...deferLoading === true ? { deferLoading } : {},                      // ← 只有显式 true 才透传
    }
  }
```

按块讲解：

- **做什么**：把内部定义投影成**模型可见的瘦身 schema**。白名单只有四个字段：`name` / `description` / `parameters`（+ 显式的 `deferLoading: true`）。
- **依赖的变量从哪来**：`definition` 来自 `view().visible`；`detachParameters` 由调用方决定要不要深克隆（`schemas()` 传 `true`，提示词组装传 `false`）。
- **与哪个知识点相关**：「`output`、`execute`、`finalizeContent`、`timeoutMs`、展示回调**绝不泄漏到线上协议**」（README 第 107 行的同一句）。`sdkSchemas` 是**唯一**例外：`ptc` 模式下 SDK 需要出参 schema 才能生成精确的返回类型，所以它单独 `snapshotJsonValue(definition.output.schema)`——注意这也是**快照**，不是引用。
- **为什么深克隆**：`snapshotJsonValue` 让调用方**改不到注册表内部**。`schemas()` 的 doc 明说 "one deep-cloned schema per visible tool"。这与 `register()` 的"借用语义"并不矛盾：**借用发生在入口**（省一次拷贝），**隔离发生在出口**（防止消费者改到内部）。

### 4.6 一个解析器喂三个消费者

#### 块 15｜`view(scope)` 全文

`packages/core/tools/src/index.ts` 第 1156–1219 行

```ts
  /**
   * Resolve every registry fact one scope needs in one layer traversal. The
   * visible map applies restrictions to the INHERITED surface, then the
   * scope's own registrations and the reserved presentation transport; the
   * other sets retain the pre-restriction facts needed by restriction and
   * prompt-order validation.
   *
   * A restriction filters what a scope inherits — the global layer and every
   * ancestor layer on its chain — and never what its OWN layer registers.
   * That exemption is what a per-child capability filter has to keep intact:
   * the delegation runtime registers a child's structured-output tool into the
   * child's own layer, and a filter naming the capabilities the child may use
   * must not strip the machinery it answers through.
   *
   * Reading the exempt set as "the global layer" instead of "not mine" held
   * only while every model-facing tool sat in the host composition. Once
   * presets moved them onto the agent plane they became an ANCESTOR
   * contribution, so a child's filter silently stopped constraining anything
   * it was given.
   * @param scope - the viewing scope (the agent), or undefined for the global view.
   * @returns the complete derived view for that scope.
   */
  private view(scope?: ScopeKey): ToolView {
    // Scope-chain layers, farthest ancestor first, the exact scope last.
    const layers = this.layers.chainLayers(scope)
    // Chain-blind on purpose: this is the ONE layer whose registrations the
    // scope owns rather than inherits, and it is absent until the scope
    // contributes something.
    const own = this.layers.peek(scope)                                  // ← 自己那一层（可能不存在）
    // Inherited surface, nearest ancestor last: a nearer scope's same-name
    // entry shadows a farther one, and the global layer is the farthest.
    const inherited = new Map<string, ToolDefinition>(this.layers.global.tools.entries())
    for (const layer of layers) {
      if (layer === own) continue                                        // ← 先把"自己"排除
      for (const [name, definition] of layer.tools.entries()) inherited.set(name, definition)
    }
    const visible = new Map<string, ToolDefinition>()
    const knownNames = new Set<string>()
    const restrictableNames = new Set<string>()
    for (const [name, definition] of inherited) {
      knownNames.add(name)                                               // ← 过滤前：也算"已知"
      restrictableNames.add(name)                                        // ← 过滤前：可被限制点名
      // Restrictions intersect across the whole chain: any scope on it may
      // mask an inherited name for everything nested inside it.
      if (layers.every(layer => layer.admits(name))) visible.set(name, definition)   // ← 交集
    }
    // The scope's own registrations last, shadowing an inherited name and
    // outside the filter above.
    if (own !== undefined) {
      for (const [name, definition] of own.tools.entries()) {
        knownNames.add(name)
        visible.set(name, definition)                                    // ← 自己的注册：不经过滤
      }
    }
    // Presentation infrastructure is resolved last and outside capability
    // filtering. Registration rejects this reserved name, so the insertion is
    // an invariant assertion as well as protection against future layer
```

按块讲解：

- **做什么**：一次遍历算出该 scope 的**三样东西**——`visible`（真正可见的定义）、`knownNames`（**过滤前**的名字集合，供 `toolOrder` 校验）、`restrictableNames`（当前可被限制点名的名字，供 `restrict()` 报"未知名"）。
- **依赖的变量从哪来**：`layers = chainLayers(scope)` 是整条链（远→近）；`own = peek(scope)` 是"只属于这个 scope"的那一层（**链盲**，故意不看祖先）；`this.layers.global` 是最远的全局层；`admits(name)` 就是 `ToolLayer` 上那个逐条检查 allow/deny 的方法（第 757–764 行）。
- **与哪个知识点相关**：这是**"一个解析器喂三个消费者"**的本体。`get()`（第 1230–1232 行）、`schemas()`（第 1260–1262 行）、`sdkSchemas()`（第 1265–1279 行）都只是它的投影；`executionMode()`（第 1303–1312 行）与 `resolveExecution()`（第 1247–1252 行）也读同一张表。
- **遮蔽怎么发生的**：`inherited` 这个 Map 先放全局层，再按"远→近"逐层 `set`——**同名后写覆盖先写**，于是"更近的 scope 遮蔽更远的"。顺序来自 `chainLayers` 的约定（注释：`farthest ancestor first, the exact scope last`）。
- **为什么要区分"继承"与"自己"**：同一段 JSDoc 讲了两件事。① 限制只筛**继承来的**工具（第 1204–1209 行的循环**不在** `layers.every(admits)` 里）；② 这条豁免对**委托运行时**是必需的——子 agent 的"结构化输出工具"注册在**子 agent 自己那一层**，child 的能力过滤不能把它赖以回答的机制一起剪掉。
- **历史教训（作者原文）**：把豁免集合读成"全局层"而不是"不是我的"，只在"所有面向模型的工具都躺在 host 组合里"时成立；preset 把它们搬到 agent 平面之后，它们变成了**祖先贡献**，于是 child 的过滤器**悄悄不再约束任何东西**。这是"作用域化注册 vs restriction"这条规则被修正的现场记录。
- **`run_code` 为什么最后插入**：它是**呈现基础设施**，不属于可过滤能力层。注册时已无条件拒绝这个名字（块 6 ③），所以这里的 `set` 既是保护也是**不变量断言**；而且它按 scope 判定——一个 native agent 绝不能因为"进程里另有 agent 用 PTC"而在自己的分派表里发现 `run_code`。

```ts
    const detached = snapshotToolValue(tool.name, candidate)             // ① 先物化成无损 JSON 快照

    } catch (error: unknown) {
```

| 维度 | `native`（默认） | `ptc` | `both` |

- `ptc` 下 SDK 生成的绑定**不代表可以直呼**——提示词里明确写着「A declaration does not make its name a directly callable tool」（packages/core/tools/README.zh.md 第 187 行）；子调用（带 `parent` token）绕过折叠，所以 `run_code` 程序里每个可见工具都能用（index.ts 第 1247–1252、1351–1353 行）。

```ts
   * The form this agent's model sees. `native` sends every visible schema,
   * `ptc` sends only `run_code` plus a generated SDK, `both` sends both.
   * Required rather than defaulted: the deployment default is what a preset

}

/** Runtime schema. */
export const Config: z<Config> = z.object({
  mode: z.union(['native', 'ptc', 'both'] as const).required(),
})

export function apply(ctx: Context, config: Config): void {
  // `presentAs` is itself the effect — it registers through the calling
  // context and hands back that exact disposer — so the declaration unwinds
  // with this row without a second wrapper owning it.
  if (config.mode === 'native') {
    ctx.tools.presentAs('native')                                       // ← native：直接声明，不等运行时
    return
  }
  // The wait is the loud failure: an entry still pending on `ptcRuntime` is
  // what `dsh-agent-preset-registry` reports as an unusable row, naming this id.

  })
```

- **为什么 `Config.mode` 是必填**：doc 原文——"the deployment default is what a preset without this row already gets, so an omitted value would mean the row was composed for nothing"（不写就是白挂一行）。

- **它的模块注释解释了平面划分**（第 1–19 行）：工具注册表必须留在 host 平面（agent loop 的调度器、API 的 presenter、每个工具插件都是它的消费者），而"呈现"可以上 preset。

### 6.3 函数级探针一：`defineTool` 编译 + `validateArgs` 违规

探针文件写在系统临时目录，**导入用绝对路径**（`<repo>` 用正斜杠替换）：

```ts
import { defineTool, validateArgs } from '<repo>/packages/core/tools/src/index.ts'
const t = defineTool({
  name: 'demo', description: 'demo',
  parameters: { a: { type: 'string', required: true }, b: { type: 'number' } },
  output: { schema: { type: 'json' }, render: () => [] },
  async execute() { return {} },
})
console.log(JSON.stringify(t.parameters))
console.log(JSON.stringify(validateArgs({ a: { type: 'string', required: true }, b: { type: 'number' } }, {})))
console.log(JSON.stringify(validateArgs({ a: { type: 'string', required: true }, b: { type: 'number' } }, { a: 'x', b: 'y' })))
```

实测输出：

```
{"type":"object","properties":{"a":{"type":"string"},"b":{"type":"number"}},"required":["a"]}
["missing required property \"a\""]
["\"b\" must be a number"]
```

三点被证实：

1. 隐式属性表里 `required: true` 的逐属性注解被**收集成 `required` 数组**（不是留在属性上）；
2. 缺必填报 `missing required property "a"`；
3. 类型不符报 `"b" must be a number`——路径就是属性名，**没有前导点**，因为根是隐式对象（§4.7 块 16 的 `propertyPath`）。

### 6.4 函数级探针二：DSL 边界

```ts
const base = { name: 'd', description: 'd', output: { schema: { type: 'json' }, render: () => [] }, async execute() { return {} } }
for (const [label, parameters] of [
  ['explicit-object-without-openness', { o: { type: 'object', properties: { k: { type: 'string' } } } }],
  ['unsupported-keyword', { s: { type: 'string', maxLength: 3 } }],
  ['oneOf-two-branches', { u: { oneOf: [{ type: 'string' }, { type: 'number' }] } }],
]) {
  try { const t = defineTool({ ...base, parameters }); console.log(label, 'OK', JSON.stringify(t.parameters)) }
  catch (error) { console.log(label, String(error.constructor.name) + ': ' + String(error.message)) }
}
const jsonTool = defineTool({ ...base, parameters: { u: { type: 'json' } } })
console.log('json-node-schema', JSON.stringify(jsonTool.parameters))
console.log('oneOf-violation', JSON.stringify(validateArgs({ u: { oneOf: [{ type: 'string' }, { type: 'number' }] } }, { u: true })))
```

实测输出（逐行）：

```
explicit-object-without-openness JsonSchemaError: unsupported JSON schema: parameters.o.additionalProperties must be explicitly true or false
unsupported-keyword JsonSchemaError: unsupported JSON schema: parameters.s.maxLength is not supported by the value schema DSL
oneOf-two-branches OK {"type":"object","properties":{"u":{"oneOf":[{"type":"string"},{"type":"number"}]}}}
json-node-schema {"type":"object","properties":{"u":{}}}
oneOf-violation ["\"u\" must match exactly one oneOf branch (matched 0)"]
```

证实：

- 显式对象漏写 `additionalProperties` **直接失败**（不是"默认开放"）；
- `maxLength` 属于**不受支持关键字**——报错原文是 `is not supported by the value schema DSL`，即**注册即报错，不是被忽略**；
- `oneOf` 两支可编译，判定是"**恰好一个分支**"（`matched 0` 表示一个都没中）；
- `{type:'json'}` 编译成**注解为空**的 schema（`{}`），也就是"无约束、但仍要求无损 JSON"。

## 附录 A 关键问题与答案

### Q1 工具如何被声明与注册？schema 从哪来？

**答案**：声明 = `defineTool({...})`，注册 = `ctx.tools.register(definition)`，两者都在插件 `apply(ctx)` 里完成，注册是效应（dispose 即注销）。

- schema 有**两个根**：`parameters`（`ParameterSchemaSpec`，**隐式开放对象根**，逐属性写 `required: true`）与 `output.schema`（`ValueSchemaSpec`，根可以是对象/数组/标量/null）。出处：packages/core/tools/src/schema.ts 第 96–111、483–515 行。
- 它们在 `defineTool()` 调用时**立即编译**成原始 JSON Schema：`parameterSchemaSpecToJsonSchema(options.parameters)` 与 `valueSchemaSpecToJsonSchema(options.output.schema)`（同文件第 577–578 行），并各自过一遍 `assertSupportedJsonSchema`（第 440、456 行）。
- 注册表再用 `schemaOf()` 投影成模型可见的 `ToolSchema`，只保留 `name`/`description`/`parameters`（+ 显式 `deferLoading`），并且 `parameters` 是**快照深克隆**（packages/core/tools/src/index.ts 第 1282–1294 行）。注册时还会**再断言一次**出参 schema 的合法性（第 1071 行）。
- 副作用边界与借用语义：注册是 `layers.effect()`（第 1083–1087 行）；注册**不克隆**你的定义对象，所以注册后不得改 schema 或换回调（docs/cookbook/adding-a-tool.zh.md 第 43 行）。
- 真实例子：`read` 工具的声明占据 packages/fs/tool-fs/src/read.ts 第 77–209 行，含 `parameters`（第 80–84 行）、`output.schema`（第 86–106 行）、`render`（第 107–120 行）、`presentationMeta`（第 124–133 行）、`isConcurrencySafe`（第 136 行）、`execute`（第 137–165 行）、`presentResult`（第 173–192 行）、`presentCall`（第 197–208 行）。同一函数**开头**还挂了一段 scope 感知的提示词段落（第 69–75 行）——它用 `ctx.tools.get('read', scope)` 判断"这个 scope 里到底有没有 read"，没有就渲染空串，这是"提示词不声明一个该 agent 看不见的工具"的落点。

### Q2 工具模式 native / ptc / both 的差别？

**答案**：差别在**模型看到什么**以及**模型能直呼什么**，两点都随模式变；两者由 `wireSchemas()`（第 1008–1029 行）与 `collapses()`（第 1351–1353 行）分别实现，判据都来自 `modeFor(scope)`（第 922–933 行）。完整对照见 §5 的表。

补充一句最容易踩的：`both` 模式下 `tools:ptc-only` 段**渲染为空**（第 873 行 JSDoc + 第 882 行的三元），因为 `both` 下 native 调用**确实能执行**——那条"只能从程序里调"的规则在这里是假的，所以不能说。

### Q3 参数如何校验？`presentAs` 之类的按 agent 呈现字段做什么？

**答案**：参数走「**编译期收紧 + 调用期校验**」两级；`presentAs` **不是字段而是方法**，作用是给一个 scope（preset/agent）覆盖 deployment 的呈现模式。

- 编译期收紧：DSL 的白名单只接受九种取值与四个注解（`schema.ts` 第 193–197 行 `assertAuthorKeys`）；显式对象的开放性必填（第 367–369 行）；`oneOf` 至少两支且不得与 `type` 并存（第 340–343 行）。
- 调用期：`execute` 包装器先 `validate(args)`，违规抛 `ToolArgsError`（`INVALID_ARGS`），因此工具主体只在参数合法时运行（第 597–601 行）。校验器返回**全部**路径限定违规而不是首错即停（packages/core/tools/src/json-schema.ts 第 646–655 行的函数 doc）；能表达的约束是类型、必填键、`enum`/`const`、`additionalProperties`、`items`、恰好一个 `oneOf` 分支；**表达不了**的（非空串、正数、跨字段）得作者自己查（docs/cookbook/adding-a-tool.zh.md 第 42 行）。
- 注册的**借用语义**会保护执行身份：`arguments` 被物化成分离的无损 JSON 并在策略开始前**冻结**，`callId`/`name`/`arguments`/`agent`/`token`/`signal`/`parent` 全程不可变；只有 around-dispatch 包装器能替换并恢复 `exec.signal` 来施加截止时间（index.ts 第 1441–1445 行；docs/cookbook/adding-a-tool.zh.md 第 44 行）。
- 展示路径单独**软校验**：`presentCall`/`presentResult` 参数不合法则返回 `undefined`，UI 回退到通用卡片（标题 = 工具名、原始 args 作为输入），因为展示会在**日志回放**时对历史参数运行，绝不能崩（packages/core/tools/src/schema.ts 第 609–624 行；卡片词汇见 packages/core/tools/src/presentation.ts 第 10–75 行）。`isConcurrencySafe` 同样软校验，不合法退化为 `false`（第 625–630 行）。
- `presentAs(mode)` 做三件事：在调用 scope 的 layer 上写那唯一一个 `mode` 格子（第 986–987 行）、非 native 时补挂 collapse 段与 SDK 段（第 995–998 行）、返回精确 disposer 恢复 deployment 默认（第 1001 行）。它**必须**来自 scoped context——全局呈现只能通过插件行的 `mode` 配置字段（第 976–978 行的报错原文）。冲突策略是"一个组合选一种呈现"：同 scope 第二次声明直接抛错（第 983–985 行）。消费者示例见 packages/core/agent-tool-presentation/src/index.ts 第 30–72 行：`native` 直接声明，非 native 则先 `ctx.inject(['ptcRuntime'], …)` 再声明（`Config.mode` 是必填字段，第 46 行）。

### Q4 作用域化注册与 restriction 如何影响工具集合？

**答案**：作用域化注册做**遮蔽**，restriction 做**过滤**，两者在 `view()` 里合成同一个 `visible` 映射，再由提示词组装、`get()`、`schemas()`、执行解析共用——所以不存在"提示词里看不到但能调"的缝。

- 遮蔽：`register()` 在哪个 ctx 调用就进哪一层的 `NamedEntries`（第 1083–1087 行）；`view()` 先铺"继承面"（全局 → 链上更近的层依次覆盖，第 1187–1191 行），再叠加**自身层**（第 1204–1209 行），因此更近的 scope 遮蔽更远的。同名同层冲突报错，且全局层的报错文案引导作者改用 `agent.ctx`（第 746–749 行）。测试断言见 packages/core/tools/tests/scoped.spec.ts 第 87–98 行（同名遮蔽在两种注册顺序下都成立）与第 100–107 行（两种冲突文案）。
- 过滤：`restrict({allow?,deny?})` 把只读数组**编译成 Set** 后存进匿名表（第 1107–1110 行），因此后续改原数组不影响已生效的限制（这是 scoped.spec.ts 第 173–182 行「compiles the readonly filter values at registration」断言的行为：注册后往 `filter.deny` 里 push 一个名字，作用域的可见集合**不变**）。`allow` 只留列出的、`deny` 去掉列出的，同一 scope 可叠加多条。多重限制在 `view()` 里用 `layers.every(layer => layer.admits(name))` **取交集**（第 1198–1201 行），`ToolLayer.admits()` 逐条检查 allow/deny（第 757–764 行）。叠加与独立解除见 scoped.spec.ts 第 161–171 行（提升 allow 之后 deny 仍在）。
- **关键不对称**：restriction 只筛「继承来的」工具，绝不筛本 scope 自己注册的（`view()` JSDoc 第 1156–1174 行 + 第 1204–1209 行）。这是必须的——委托运行时把子 agent 的结构化输出工具注册进子 agent 自己的层，child 的能力过滤不能把"它赖以回答的机制"一起剪掉。
- 作用范围：限制只对自己及嵌套其下的 scope 生效，不污染其他 scope 或全局视图（scoped.spec.ts 第 130–135 行断言作用域内是 `['capture','read']`、全局视图仍是 `['bash','read']`）。dispose 时解除（`layers.effect` 的逆操作，第 1119–1123 行）。
- 三条拒绝规则（第 1097–1118 行）：必须来自 scoped context（否则「会掩掉每个 agent」，报错里给出替代方案「对目标 agent 用 deny」）；空过滤器 `restrict({})` 直接拒绝（理由是它几乎总是"配置被物化成空"的 bug）；**未知名直接报错并列出所有已知全局工具**；`RUN_CODE_NAME` 既不能 allow 也不能 deny——「restrict end-capability tools instead」。
- 真实用法：subagent 的 `toolFilter` 在有作用域的子 agent 创建窗口内调用 `tools.restrict()`，效果是"被点名的工具从 child 的提示词里消失**且**拒绝执行（一份可见性）"（packages/subagent/subagent/src/child-agent.ts 第 218 行；packages/subagent/subagent/src/types.ts 第 185–192 行）。同一机制被用于把 schema 可见性与指引一起收紧，而不是只藏 schema（.agents/notes/implemented/architecture/2026-08-10-fork-children-stay-one-shot.zh.md 第 29 行记录了这个否决项）。另一处真实调用见 packages/experimental/browser-use-runtime/src/mcp.ts 第 117 行（继承工具整体 deny）。

### Q6（第一次读请跳过）守卫与审批谁先谁后？为什么守卫"单调"？

**答案**：顺序是 `tools/pre-execute` waterfall → （若返回 `ask`）审批服务 → 守卫 → `tools/execute`。

- 出处：`prepareExecution()`（index.ts 第 1503–1535 行）——先 `waterfall('tools/pre-execute', …, () => ({kind:'allow'}))`；`gate.kind === 'ask'` 时调 `this.serviceAsk(exec, gate)`（第 1509–1511 行）；然后 `const denialReason = decision.kind === 'allow' ? this.guardReason(exec) : decision.reason`（第 1519 行）——**只有被允许的调用才会去问守卫**。
- "单调"的含义：`ToolGuard` 的返回值是 `string | undefined`（拒绝理由或不管），**没有 allow**；所以排在后面的监听器无法把前面的拒绝翻回允许（doc 第 722–731 行）。守卫的查找顺序是"先全局、再链上由远及近"（`guardReason()`，第 1144–1154 行），第一个给出理由的就终判。
- 与 `ask` 的关系：`ask` 需要审批服务返回 `allowed-once`，否则**等价于 deny**（`PreToolDecision` 的 doc 第 598–611 行）；如果审批通道本身报告了取消，则走"取消"结果而不是拒绝（第 1513–1515 行）。
- 这一节的全部把关点与逐节点说明归 `3.10`；本课只需要知道"守卫在注册表侧就是 `ToolLayer.guards` 那张匿名表，注册方式是 `ctx.tools.guard()`（第 1136–1142 行）"。

### Q7（第一次读请跳过）为什么 PTC 运行时不用 static `inject`？

**答案**：因为那会让 **native 部署也被 PTC 运行时的存在与否劫持**。

- 出处：`requirePtcRuntime()` 的 doc（index.ts 第 1031–1044 行）原文——"Read at use time (assembly / run_code execution), NOT via static `inject`: an inject entry would hold `ctx.tools` — and every tool plugin behind it — hostage to a PTC runtime existing even under `mode: 'native'`."
- 落地方式：`requirePtcRuntime(mode)`（第 1045–1055 行）在使用时 `this.ctx.get('ptcRuntime')`，缺失就给一条**可操作**的报错（告诉你可以装哪个实现、或把 mode 改回 `native`）；语言没有渲染器时列出已知语言。
- 与 `presentAs` 的配合：agent 平面那一行（`packages/core/agent-tool-presentation/src/index.ts`）也遵循同一原则——`inject = ['tools']` 里**不写** `ptcRuntime`，而是"非 native 时才 `ctx.inject(['ptcRuntime'], …)`"（第 69–71 行），于是 native 行在没有运行时的部署里照样能挂。
- 同时也解释了"为什么它是在**组装期**报错"：`wireSchemas()` 在做 schema 投影**之前**就先 `requirePtcRuntime(mode)`（第 1020 行），让"这个语言没有 SDK 渲染器"成为组装期的唯一权威错误——**故意在组装期而非首次提问期失败**。
