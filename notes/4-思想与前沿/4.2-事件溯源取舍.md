## 0. 怎么读这一课

### 0.1 这一课是什么、不是什么

**是**：一条设计选择的完整账——事件溯源换来了什么、付出了什么、**如果允许改写历史会同时失去哪 8 条保证**。
**不是**：session 的 API 用法（第三编）、压缩怎么触发（`3.12`）、迁移链每一跳的字段级规则（`4.5` 与各迁移边 README）。

### 0.2 现在只要记住这 5 件事

1. **只有一份真源：只追加的事件日志。** 模型历史（transcript）、遥测、标题、持久化**全部从它派生**，不许自己另存一份。
2. **追加是唯一写入口。** 代码里**没有** `update` / `delete` / `splice`——想改模型看到的内容，只能再追加一个「遮蔽前面几个节点」的新事件。
3. **于是「状态」是算出来的，不是存下来的。** 所以「状态与日志分歧」这类 bug 在结构上不可能发生。
4. **遮罩发生在派生层（surface），不在日志层。** 压缩之后，日志里旧消息**仍在**，只是不再进模型输入。
5. **代价集中在一处：格式只能往前长。** 于是旧日志靠一条**静态、相邻、每包一步**的迁移链读成当前格式，而不是原地改写。

### 0.3 明确授权：这些现在不用管

- `surface` 的**位置替换算法**（`replaceGeneration` / `contentGeneration` 怎么走）——第一次读不必弄懂，知道它「遮蔽而不删除」就够了；源码在 §3.4。
- 迁移链**每一跳的字段级改名规则**（v0→v1 改了什么名、v2→v3 的 delivery guard 具体条目）——属于 `4.5` 与各迁移边 README，本课只用到「相邻 + 每包一步 + 不落中间盘」这三条。
- `assistant/attempt` 里的**紧凑 stream 编码**（compact run 怎么合成）——属于 `4.3`，本课只用到「一个 attempt 一个原子单位」这个结论。

其余的词，附录 B 给了「在本课是否已定义 + 在哪一课展开」。

## 1. 最小词汇表（本课新增的 6 个词）

| 词 | 大白话 | 源码里的写法 |
|---|---|---|
| **event sourcing 事件溯源** | 不存「当前状态」，只存「发生过的事」，当前状态每次**算**出来 | `Session` 是唯一真源，别的一切都从它派生 |
| **append-only 只追加** | 只能往末尾加，**不能改、不能删**中间已有的那条 | 只有 `append()`，没有 `update()` / `delete()` |
| **derive 派生** | 从日志**投影**出你要的那份视图 | `deriveMessages()` 投影出模型历史 |
| **surface 表层** | 「哪些条目算进模型输入、按什么顺序」的那份**有序视图** | `surface.nodes`、`surfaceOp` 标记 |
| **settlement 结算** | 一次模型尝试**恰好**留下一个持久单位（成功或失败都一样） | `assistant/message` 或 `assistant/attempt` |
| **generation 代际** | 磁盘上同一个会话的**某一版文件**，文件名带版本号 | `session.jsonl`（v0）／`session.v4.jsonl` |

> ⚠️ 这 6 个词里有 4 个（`surface` / `settlement` / `generation` / `derive`）在源码里就是英文原词，本笔记之后**只用英文名**；中文只在上面这张表里注解这一次。

## 2. 先建立画面

### 2.1 「三层真相」从属关系（静态结构）

本课最反直觉的地方是：**同一句话在系统里有三个位置，而只有最底下那层是历史。**

```
① 日志层（真源，只增不减）
   Session.log：一维数组，下标就是 seq
   └─ 每条事件 { type, seq, time, data }，追加后深度冻结
        │
        │  deriveMessages() 投影（只读）
        ▼
② 派生层（随时可重算，允许「遮蔽」）
   surface.nodes：哪几条算进模型输入、什么顺序
   └─ 压缩 = 追加一个 replace 事件，让旧节点不再进 surface
        │
        │  写盘时编码
        ▼
③ 磁盘层（同一份日志的若干个「代际」）
   session.jsonl / session.vN.jsonl[.zstd]
   └─ 旧代际永不改名、永不删除；新代际写在旁边
```

> **精确性说明**：② 不是 ① 的子集副本，而是 ① 的**函数**——`deriveMessages()` 每次调用都按 `surface` 从 `log` 现算；图上画成上下层只为表示「谁依赖谁」。
> **精确性说明**：③ 与 ① 不是包含关系，而是「编码前 / 编码后」；同一份日志可以有多个代际同时躺在磁盘上（§4.3）。

### 2.2 一次 append 的次序（动态过程）

```
append(type, data, opts?)
  1. 摘出 surfaceOp / sourceEventSeqs 元数据        ← 只有 surface 事件才允许带
  2. snapshotJsonValue(data) —— 无损 JSON 快照       非无损 → 直接抛
  3. 重入检查（appending 边界）                       重入 → 直接抛
  4. deepFreeze({ type, seq: log.length, time: now, data })
  5. validateSessionEventData + surfaceManager.validateNext
  6. 置位 appending，**先取监听器快照**
  7. this.log.push(event)   ← ★ 提交点，从这里起事实已成立
  8. 提交后才广播 session/event（回调异常被隔离）
  9. finally 复位 appending，处理延迟 detach
```

> 顺序的要点在 **7 与 8 之间**：**先落日志，再通知**。所以「通知里抛异常」改不了已提交的事实——这正是「日志即状态」的写法。

### 2.3 大白话版：一个只写不涂的账本

**完全不用上面的术语**（来源：`packages\core\session\README.zh.md` 第 88 行的设计理念一段，这里只做白话转述）：

1. 有个账本，**只能用钢笔往后面写**，写完一行就用胶带封住，这一行谁都改不了。
2. 你想知道「现在账上还剩多少钱」？不看某个「余额」字段，而是**从头把每一笔重算一遍**。
3. 有一天要作废前面三笔——做法不是撕掉，而是**再写一行**：「从第 4 笔到第 6 笔不再算数，用这一笔代替」。
4. 于是账本上作废的那三笔**字还在**，只是重算时不再算它们。谁想知道「当时真正写了什么」，翻开就看得到。
5. 万一你想看「上个月那版账本」，旧账本**没被覆盖**，还放在旁边那个写着版本号的抽屉里。
6. 想让旧账本按新格式读，就写一串**一步一步**的翻译说明（v0→v1→v2→…），每一页翻译只负责相邻两年，翻译结果**写成一个新抽屉**，旧的不动。

这就是本课的全部内容：**为什么第 2 步要重算、第 3 步为什么不撕、第 5–6 步为什么必须一步一步。**

### 3.2 append 是唯一写入口（源码块 1）

`packages\core\session\src\index.ts` 第 718–769 行

```ts
  append<T extends SessionEventType>(               // ← 块开头：唯一的写入方法
    type: T,
    data: SessionEventMap[T],
    ...opts: T extends SurfaceEventType ? [opts: SurfaceIntent<T>] : []
  ): SessionEvent<T> {
    const surfaceOpts: SurfaceIntent | undefined = opts[0]      // ← 元数据从调用方传入
    const surfaceMetadata = {
      ...surfaceOpts?.sourceEventSeqs === undefined ? {} : { sourceEventSeqs: surfaceOpts.sourceEventSeqs },
      ...surfaceOpts?.surfaceOp === undefined ? {} : { surfaceOp: surfaceOpts.surfaceOp },
    }
    const dataSnapshot = snapshotJsonValue(data)                 // ① 无损 JSON 快照
    if (dataSnapshot === undefined) {
      throw new Error(`session event "${type}" carries non-JSON-serializable data`)
    }
    const surfaceMetadataSnapshot = snapshotJsonValue(surfaceMetadata)
    if (surfaceMetadataSnapshot === undefined) {
      throw new Error(`session event "${type}" carries non-JSON-serializable surface metadata`)
    }
    const entry = attachments.get(this)                          // ② 重入边界就挂在这个 entry 上
    if (entry?.appending) {
      throw new Error('session append cannot reenter while another append is being published')
    }
    const event = deepFreeze({                                   // ③ 先冻结，再校验
      type,
      seq: SessionSeq(this.log.length),                          // ④ seq = 当前日志长度（只增不减）
      time: Date.now(),
      data: dataSnapshot,
      ...(surfaceMetadataSnapshot as { surfaceOp?: unknown; sourceEventSeqs?: unknown }),
    } as unknown as SessionEvent<T>)
    validateSessionEventData(event, `session event "${type}" at seq ${event.seq}`)
    this.surfaceManager.validateNext(event as SessionEvent)      // ⑤ 表层契约校验
    // …（第 750–768 行：置位 appending → 取监听器快照 → this.log.push(event) 提交点
    //   → 提交后广播 session/event → finally 复位。这一段是本块 ①–⑤ 的直接下文，
    //   与「只追加」这个知识点无关，属于「事件怎么被通知」，此处省略）
    return event
  }
```

按块讲解（对应知识点：**追加是唯一写入口 · 写入前先校验**）：

- **块开头那一行** `append<T extends SessionEventType>(…)` 就是本课的落点：**这个类上没有任何 `update` / `delete` / `splice`**，日志的唯一变更方式是它（§6 探针 1 用 `Object.getOwnPropertyNames` 实测过成员清单）。
- **`surfaceOpts` 从哪来**：调用方的第三个参数；`...opts` 是条件类型——只有 `SurfaceEventType`（`system/message`、`developer/message`、`user/message`、`assistant/message`、`tool/result`）**才允许**传它，其它类型传了编译不过（类型定义见 §3.4 的源码块 4、5）。
- **① `snapshotJsonValue`**：把载荷**分离式快照**一遍。作者在方法 JSDoc 里写明理由：*"One iterative pass reads, validates, and copies each nested value once, so a stateful getter cannot supply one value to validation and another to storage."*（有状态的 getter 不能让校验看到一个值、存储看到另一个值。）
- **③ `deepFreeze`**：事件对象**冻结**。所以「改历史」在运行时也不成立——§6 探针 2 实测 `Reflect.set` 返回 `false`（静默失败）。
- **④ `seq: SessionSeq(this.log.length)`**：序号**就是数组下标**，不是计数器。这一句同时保证了「只增不减、不可复用」——因为数组只 `push`。
- **⑤ 两个校验在 `push` 之前**：所以「被拒绝的追加不改变日志」不是靠回滚，而是**根本还没进日志**（`packages\core\session\README.zh.md` 第 56 行；§6 探针 5 实测两次拒绝后 `seq` 仍是 1）。
- 省略的 750–768 行回答的是「事件进入日志后怎么被通知」，与「只能追加」无关；它的结论（先提交后广播）已在 §2.2 的第 7–8 步给出。

按块讲解（对应知识点：**事件基数是协议 · settlement 的两种形态**）：

- **`SessionEventMap` 是一个接口**，插件可以用声明合并往里加成员（2026-06-11 Note 第 27 行：「事件词汇可通过合并扩展（插件可添加如压缩事件）」）。`SessionEventType = keyof SessionEventMap` 于是自动包含插件加的类型——这就是「事件词汇是开放集合」的落点。
- **`assistant/message` 与 `assistant/attempt` 是同一件事的两个出口**：前者带组装后的 `message`（进模型历史），后者**没有 `message` 字段**——字段的缺席本身就是「这次尝试不要进模型历史」的表达。
- **两者都带 `stream: AssistantStreamRecord[]`**：所以「一个 attempt 恰好一个持久单位」是**类型层面**的：想给某个 attempt 存两段证据，无处可放。
- **`SESSION_FORMAT_VERSION = 4`**：当前写入版本。它的 JSDoc（第 67–88 行，此处省略）写明了加版本的判据：*"bump exactly when an older runtime could no longer handle a new log with full semantic correctness"*，以及 *"Adding an ordinary event type does not bump"*——**加事件类型**和**改格式**是两件事，这正是「基数变化才昂贵」的来源（§5 代价 3）。

### 3.4 遮蔽 ≠ 删除：`surfaceOp` 的类型规则（源码块 4、5）

**源码块 4** —— `packages\core\session\src\types.ts` 第 449–478 行

```ts
/**
 * How a session event entered the ordered surface. Only valid on
 * {@link SurfaceEventType} events.
 * - `'append'`: added to the tail — normal path for user/assistant/tool messages.
 * - `{ op: 'replace', startSeq, endSeq }`: replaces surface nodes from `startSeq`
 *   (inclusive) through `endSeq` (inclusive) with this node. Both must exist as
 *   surface nodes in the current surface. `startSeq === endSeq` replaces a single
 *   node. The node's {@link SessionEvent.sourceEventSeqs} must include every
 *   shadowed surface node. Used by compaction; any surface-replacing producer may use it.
 */
export type SurfaceOp =
  | 'append'                                                  // ← 普通追加
  | { op: 'replace'; startSeq: SessionSeq; endSeq: SessionSeq } // ← 遮蔽一段

/**
 * Surface placement and cited source-event seqs for {@link Session.append}. Required on
 * message-producing events and forbidden on log-only events.
 */
export type SurfaceIntent<T extends SurfaceEventType = SurfaceEventType> = {
  surfaceOp: SurfaceOp
} & (T extends 'assistant/message' ? {
  /** Assistant messages embed their provider stream instead of citing source events. */
  sourceEventSeqs?: never
} : {
  /** Complete non-empty set of known earlier source-event seqs. */
  sourceEventSeqs?: SessionSeq[]
})
```

**源码块 5** —— `packages\core\session\src\types.ts` 第 434–447 行

```ts
/**
 * The subset of {@link SessionEventType} values whose events produce LLM
 * messages and are eligible to appear on the ordered surface. Only these
 * event types may carry {@link SurfaceOp}; system, user, and tool events may also cite
 * earlier sources through {@link SessionEvent.sourceEventSeqs}.
 */
export type SurfaceEventType =
  | 'system/message'
  | 'developer/message'
  | 'user/message'
  | 'assistant/message'
  | 'tool/result'

/** A message-producing event carrying its required surface operation. */
export type SurfaceEvent = SessionEvent<SurfaceEventType>
```

按块讲解（对应知识点：**压缩只在派生层发生**）：

- **`SurfaceOp` 只有两个取值**：`'append'` 和 `{ op: 'replace', startSeq, endSeq }`。**没有 `'delete'`**——想「删掉模型看到的一段」，唯一表达方式是 `replace` 一个**替代节点**上去。这就是「遮蔽而非删除」在类型上的落地。
- **`startSeq` / `endSeq` 都在当前 surface 里必须存在**（JSDoc 原文 "Both must exist as surface nodes in the current surface"）。所以 `replace` 不是「按日志序号删」，而是「按**当前模型视图**的位置替换」——这正是 §2.1 里「② 是①的函数」的直接后果。
- **`sourceEventSeqs` 必须完整覆盖被遮蔽的节点**（原文 "must include every shadowed surface node"）：被遮蔽的事实仍要**指着原事件**，否则遮蔽就成了无出处的删除。这条由 `surfaceManager.validateNext` 在 §3.2 的 ⑤ 处强制。
- **`assistant/message` 的 `sourceEventSeqs?: never`**：assistant 消息自带 provider stream，**禁止**引用顶层源事件——类型上写死，不是约定。
- **`SurfaceEventType` 这 5 个类型是白名单**：`turn/start`、`assistant/attempt` 这类仅日志事件**禁止**带 surface 元数据（`SessionEvent` 的 JSDoc 原文："the compiler enforces this at `Session.append()` call sites"）。

### 3.5 派生是增量 + 缓存，返回的永远是冻结的新数组（源码块 6）

```ts
  deriveMessages(): Message[] {                      // ← 块开头
    const surface = this.surface
    const nodes = surface.nodes                      // ① 「哪些日志下标进模型输入」
    const generation = surface.contentGeneration     // ② 替换/插件投影的代数
    if (generation !== this.derivedGeneration) {     // ③ 代数变了 → 整体重建
      this.derived = []
      this.derivedNodes = 0
      this.derivedGeneration = generation
    }
    for (const seq of nodes.slice(this.derivedNodes)) {   // ④ 否则只投影新增的节点
      // Surface sequences are built from this.log — seq is always a valid
      // index by construction. The non-null assertion expresses that invariant.
      // oxlint-disable-next-line typescript/no-non-null-assertion
      const msg = this.deriveEventMessage(this.log[seq]!)   // ⑤ 从日志里取那一条
      // A surface node is one of the five message-producing types, but an
      // empty-content assistant/message (a max-tokens step that hosts only
      // usage) derives to null and must not enter the transcript.
      if (msg) this.derived.push(msg)
    }
    this.derivedNodes = nodes.length
    return [...this.derived]                         // ⑥ 每次返回新数组（元素是共享冻结的）
  }
```

按块讲解（对应知识点：**派生成本随日志长度增长**）：

- **输入是什么**：`surface.nodes` 是一串**日志下标**（`①`），`contentGeneration` 是「发生过替换或插件消息投影」的代数（`②`）。函数本身**不改任何状态**，只读 `log`。
- **③ 什么时候整体重建**：`generation` 变了（也就是发生了 `replace` 或插件投影）就把缓存放掉重算。
- **④ 平时只算新增**：`nodes.slice(this.derivedNodes)`——纯尾部追加时，成本只与**新节点数**成正比。作者的 JSDoc 原文：*"pure tail growth costs O(new nodes); a replacement or message projection rebuilds"*。
- **⑥ 返回的是新数组**：`[...this.derived]`。所以「调用方拿到的数组不会被后续 append 撑大」；数组元素（`Message`）是**共享且深度冻结**的——**通过派生结果改日志是做不到的**（2026-07-05 Note 第 23 行把这句写成了「通过投影变异已记录的历史是不可表达的（会抛异常）」）。
- **这与「代价 1」直接对应**：既然每次都是「从日志现算」，**日志越长，全量重建越贵**。所以 2026-06-11 Note 第 28 行给的缓解手段是**压缩**，而不是「改写日志让它变短」。

```ts
/**
 * Copy an inclusive event prefix, mark its inherited cut, and close its open tail with forked results
 * and step/turn endings. Closed steps and turns are preserved unchanged.
 * …
 * @param boundary - inclusive source event seq the child inherits through.
 */
export function buildForkSeed(events: readonly SessionEvent[], boundary: SessionSeqType): SessionEvent[] {
  const prefix = events.slice(0, boundary + 1)     // ① 复制「包含切点」的前缀
  prefix.push({
```

按块讲解（对应知识点：**fork 就是「用已有日志初始化新会话」**）：

- **① `events.slice(0, boundary + 1)`**：fork 是**按序号切一段拷贝**，不是「按当前状态重建一份」。子会话拿到的是**同一批事件对象**（JSDoc 原文："a new array retaining the source event objects"）。
- **② 标记的位置**：`seq: boundary + 1`，正好落在继承前缀之后。`buildForkSeed` 返回的数组 = 前缀 + 标记 + 补的结束事件；`inheritedEventCount` 只数前缀（`packages\core\session\README.zh.md` 第 68 行：「标记和结束事件属于子会话；`inheritedEventCount` 只统计复制的前缀」）。
- **③ `openTurnClosers`**：**只**给「还开着的步骤/轮次」补结束事件，已闭合的原样保留（JSDoc 原文："Closed steps and turns are preserved unchanged"）——所以 fork 不会为了「好看」去改写历史里已有的收尾。
- **这一块为什么是「只追加」的证据**：整个 fork 过程**没有一处修改入参**，`prefix` 是新数组，`push` 只往新数组尾部加。§6 探针 4 实测：父会话 seq 2、派生 1；子会话 `inheritedEventCount: 2`、`isOwnSeq(0): false`、`ownEvents` 只有 `session/end-seed, turn/end`。

### 3.8 迁移链：相邻性是编译期契约（源码块 9）

`packages\session\session-format\src\chain.ts` 第 19–77 行

```ts
/**
 * Validate and freeze one adjacent migration declaration.
 * @param migration - named exact adjacent conversion.
 * @returns immutable validated declaration.
 */
export function defineSessionFormatMigration(migration: SessionFormatMigration): SessionFormatMigration {
  if (typeof migration.name !== 'string' || migration.name.length === 0) {
    throw new SessionFormatError('Session migration name must be a non-empty string')
  }
  const from = sessionFormatVersion(migration.fromVersion, `${migration.name} fromVersion`)
  const to = sessionFormatVersion(migration.toVersion, `${migration.name} toVersion`)
  if (to !== from + 1) {                                    // ① 只允许相邻一跳
    throw new SessionFormatError(`${migration.name} must declare adjacent v${from}->v${from + 1}`)
  }
  return Object.freeze({ ...migration })                    // ② 声明本身冻结
}

class CompiledSessionFormatChain implements SessionFormatChain {
  readonly currentVersion: number
  // …（第 47–49 行：三个私有字段；第 50–51 行是 `constructor(options)` 与
  //   `currentVersion` 赋值，此处省略）
  constructor(options: SessionFormatChainOptions) {

    this.restoreCurrentHeader = options.restoreCurrentHeader

      byFrom.set(migration.fromVersion, migration)
      names.add(migration.name)
    }
    const ordered: SessionFormatMigration[] = []
    for (let version = 0; version < this.currentVersion; version += 1) {   // ④ 逐段找，缺一段就抛
      const migration = byFrom.get(version)
      if (migration === undefined) {
        throw new SessionFormatUnsupportedMigrationError(`Session migration v${version}->v${version + 1} is missing`)
      }
      ordered.push(migration)
    }
    if (byFrom.size !== ordered.length) {                       // ⑤ 多出来的边越界了 → 抛
      const invalid = [...byFrom.keys()].find(version => version >= this.currentVersion) as number
      throw new SessionFormatError(`Session migration from v${invalid} does not lead to current v${this.currentVersion}`)
    }
```

按块讲解（对应知识点：**一个包负责一步 · 缺口必须在构建期暴露**）：

- **① `to !== from + 1` 就抛**：跨版本「一步到位」的迁移**在声明处就注册不进来**。这不是注释里的约定，是 `defineSessionFormatMigration` 里的一行 `if`。
- **② 声明被 `Object.freeze`**：声明不可变，可变状态留给「每次 restore 新建的 stage」（见 2026-08-31 Note 第 28 行：*"Stage 拥有该 artifact 的可变状态；不同 Session 之间绝不共享 stage instance"*）。
- **③④⑤ 三段校验合起来就是「唯一、无缺口、不越界」**：③ 挡重复起点，④ 从 v0 一路数到 `currentVersion`，**少一段立刻抛** `Session migration vN->vN+1 is missing`，⑤ 挡「指向未来版本」的多余边。
- **校验发生在什么时候**：`CompiledSessionFormatChain` 的**构造函数**里——也就是目录装配时（`packages\session\session-format-catalog\README.zh.md` 第 12、30 行：目录「在模块初始化时校验完整且无缺口的迁移链」，功能插件**无法**注册或重排其条目）。所以**用户打开旧会话之前**，链条是否完整就已经定论。
- **这就是「改写历史会失去可证明性」的机制来源**：迁移之所以敢「只写最终 current target、把中间版本留在 stage 内存里」（2026-08-31 Note 第 114 行），前提是**源字节不动、每个已提交代际语义冻结**；链条能一段一段被证明，也是因为这个前提。

## 4. 领域知识：settlement、代际与只读准备

### 4.1 settlement：一个 attempt 恰好一个持久单位

- v2 之后**没有**顶层 `assistant/chunk` 事件；每个模型 attempt 提交**一个**含 `stream: AssistantStreamRecord[]` 的持久 settlement：成功的进 `assistant/message`，没有 surface message 的失败/重试/取消/stream error 进 `assistant/attempt`，**且不添加模型历史**（2026-09-01 Note 第 19–22 行；字段定义见 §3.3 源码块 3）。
- 紧凑化 = 「同块连续 delta 合成 run + 保留首个时间戳与精确间隔」，`expandAssistantStream()` 严格还原；**压缩绝不会合并 delta 边界**（同 Note 第 24 行）。
- 为什么不能把 stream 放 sidecar：原文写得很直——*"这会把一个 attempt 的 message 与证据拆给不同持久性 owner"*，并给出结论「**settlement 是原子 owner**」（同 Note 第 68 行）。
- **硬中断的边界被写进后果**：settlement 之前**没有**持久 attempt 证据，进程/主机在 settlement 前挂掉就丢掉整段 in-flight stream；`agent/assistant-stream` **不是 write-ahead log**（同 Note 第 76 行）。这是「只追加」付出的第一笔可观测代价。

### 4.2 代际：文件名就是版本号，旧的永不删

- 规范文件名编码物理代际：**v0 用 `session.jsonl[.zstd]`，正版本用 `session.vN.jsonl[.zstd]`**（2026-08-31 Note 第 114 行；`docs\architecture.zh.md` 第 129 行同口径）。
- *"Migration 不会移动、覆盖或删除任何 committed generation，并且只写最终 current target；中间版本只存在于 stage state."*（2026-08-31 Note 第 114 行）。
- 低代际为 operator 检查而保留：*"Retention 不承诺 downgrade compatibility、automatic fallback，也不保证旧 runtime 能安全理解新 generation."*（同 Note 第 240 行）。
- JSONL provider 负责物理 framing、压缩、代际选择与排他发布；**每个相邻迁移包只负责一个 `vN -> vN+1` 步骤**（`docs\architecture.zh.md` 第 129 行）。

### 4.3 只读准备：只追加甚至推迟了「写」

- `prepareJsonlMigration()` **只跑一遍 Stage chain** 得到 current artifact，**不 encode、不写文件**；`publish()` 幂等，并发与后续调用共享同一个终态 Promise（2026-09-05 Note 第 41 行）。
- read open **只等 preparation**；write open 复用同一 artifact 并等 publication（同 Note 第 29 行）。
- 实测口径：只读打开 **6.241s → 2.954s（-53%）**；`session.follow` 的 opening snapshot 7.587s → 2.912s（-62%）；**只读打开不发布后继**（同 Note 第 132、140–141、154 行）。
- 这条设计反过来证明「只追加」有多严格：连「为了让历史可读而顺手写一个新代际」都被当成**需要论证的副作用**，最后被推迟到第一个真正的 writer 出现时。

## 5. 账本：收益与代价

### 5.1 收益（6 条）

1. **状态与日志在结构上不可能分歧。** 替代方案「可变消息数组 + 事件仅作通知」被明确否决：*"更简单，但状态与日志可能分歧；采用事件溯源后，日志本身即是状态，分歧在结构上不可能发生"*（2026-06-11 Note 第 21 行）。这是一整类 bug 的**消灭**，不是概率降低。
2. **回放、追踪、遥测在结构上得到保证，而非事后附加**（同 Note 第 25 行）。`docs\architecture.zh.md` 第 127 行把它展开成一份派生清单。DSH 不是「顺便能回放」，而是**回放就是读日志**。
3. **模型历史成为纯函数，可逐请求重建与审计。** `request/header` 存完整规范快照，`foldRequestHeader()` 选最新快照，使每个对话请求都成为日志的纯函数（`packages\core\session\README.zh.md` 第 119 行）；「模型可见即已记录：每个模型请求都必须能从日志重建」（`docs\architecture.zh.md` 第 131 行）。
4. **KV cache 友好：追加天然保留可复用前缀。** 只有 `replace` 才从首条被遮蔽消息起使缓存复用失效（`packages\core\session\README.zh.md` 第 153 行）。2026-07-05 Note 第 19 行把它点成因果：**前缀缓存稳定性是推论 #1**，是「逐节点纯函数投影」涌现出来的，不是专门管理出来的。
5. **多消费方共享同一份证据。** 精确紧凑 stream 同时服务 Chat、Trajectory、遥测与历史页，且*"两个目标都不会为展示将已结算流展开为逐 delta 对象"*（2026-09-01 Note 第 34、74 行）。
6. **热路径不被 I/O 阻塞。** 追加同步、`session/event` 同步通知，持久化插件缓冲延后写入并在轮次末的检查点等待排空（2026-06-11 Note 第 15 行；`packages\core\session\README.zh.md` 第 74 行）。

### 5.2 代价（6 条）

1. **派生成本随日志长度增长。** 原文直说：*"派生成本随日志长度增长，压缩是预期的缓解手段，而不是改写日志"*（2026-06-11 Note 第 28 行）。量级侧证：v0 读入需要持有约 **914 万个**展开事件、**retained heap 2.016GB**（2026-08-31 Note 第 196 行）。
2. **存储只增不减，所有历史版本必须永久可读。** 已提交代际绝不重命名、替换或删除（`docs\architecture.zh.md` 第 129 行；2026-08-31 Note 第 114 行）；低代际为 operator 检查保留，retention 不承诺降级或回退（同 Note 第 240 行）。
3. **事件基数是协议，任何基数变化都要付出重映射全部引用的代价。** v1→v2 把 chunk 折成 settlement 时，必须改写信封 source-event 引用、surface 替换端点、command source event、compaction range 与 shadowed list、title message list；**指向被消费 chunk 的引用直接让迁移失败**（2026-09-01 Note 第 40 行）。原文承认这是有意的：*"该约束有意让未来的基数变化迁移保持昂贵"*（同 Note 第 80 行）。
4. **settlement 之前没有持久证据。** 进程硬中断就整段 in-flight stream 全丢；`agent/assistant-stream` 不是 WAL（2026-09-01 Note 第 76 行）。
5. **一次迁移的内存与校验是双向开销。** 每条边都 whole-artifact snapshot/deep freeze 的老实现把 116MB 日志推到 7.2GB RSS 并 OOM；改成有状态 Stage 后仍需在最终校验时展开嵌入 stream（2026-08-31 Note 第 9、128、189、197 行）。
6. **调试与运维必须理解「两层真相」**：压缩遮蔽、`replace` 端点、`sourceEventSeqs` 完整性，以及迁移中「不解释归他人所有的不透明 JSON」（2026-08-31 Note 第 76 行）。否则很容易误判「为什么日志里还有这条消息」。

### 5.3 验收题：如果允许改写历史，会失去什么（8 条）

**逐项清单（每项都对应一个真实机制，不是推测）**

1. **失去 fork 的语义基础。** fork 的定义就是「用已有日志初始化一个新会话」（2026-06-11 Note 第 13 行），`buildForkSeed` 直接 `events.slice(0, boundary + 1)`（`packages\core\session\src\fork.ts` 第 22 行，§3.7）。前缀可改写 ⇒ 同一个 `boundary` 在不同时刻意味着不同历史，fork 退化成「拷贝某个不确定的快照」；`inheritedEventCount` 与 `isOwnSeq()` 的判定同时失去意义（`packages\core\session\src\index.ts` 第 591–609、662–673 行）。
2. **失去「模型可见即已记录」的可审计性。** 该不变量的全部价值在于事后能重建当时那次请求（`docs\architecture.zh.md` 第 131 行）。改写一处历史，此后所有 `request/header` 快照与派生请求都变成对不上账的孤儿——而 DSH 恰恰把 header 做成完整快照以支持精确重建（`packages\core\session\README.zh.md` 第 92 行）。
3. **失去 KV cache 的稳定前缀，且是逐条崩坏的。** `replace` 一旦发生，缓存复用从首条被遮蔽消息起失效（`packages\core\session\README.zh.md` 第 153 行）。真正的原地改写等于**每次编辑都从第一处差异开始重建缓存**。
4. **失去跨版本迁移链的可证明性。** 迁移之所以能只写最终 current target、把中间版本留在 stage state（2026-08-31 Note 第 114 行），前提是**源字节不动、每个已提交代际语义冻结**。允许改写历史，等于放弃「每个相邻边只对一个不可变源负责」这个前提。
5. **失去迁移的确定性验收标准。** 现行验收要求比较「结果历史」与「拒绝效果」，并要求前代字节不变（2026-08-31 Note 第 174、176 行）；语料测试在还原成功与拒绝后**都**检查源字节（同 Note 第 84 行）。源可变时这些断言全部失效。
6. **失去「拒绝而不猜测」的安全姿态。** 现行设计宁可让整条链抛类型化拒绝（`SessionFormatUnsupportedMigrationError`，§3.9）、宁可让原生校验拒绝重复 start 也不放宽（2026-08-31 Note 第 92、94 行），也不静默改语义。若允许改写历史，「遇到不理解的东西就把它改写成能跑的样子」会变成默认选项。
7. **失去只读访问与写入权限的分离。** read open 只等 preparation、不发布代际（2026-09-05 Note 第 29、154 行）之所以成立，是因为读**不需要动源**。允许改写后，**读历史本身就变成一次写操作**。
8. **失去遥测 / 标题 / transcript 的一致基准。** 这些都在 `docs\architecture.zh.md` 第 127 行的同一份派生清单里。历史可变 ⇒ 同一 session 的同一 `seq` 在不同时间代表不同事实 ⇒ 所有下游指标的同比、归档、复现全部不可信。

**一句话结论**：允许改写历史省掉的是「迁移链 + 代际发布」这段工程量，换来的是**上述 8 条保证同时失效**。对 DSH 这类以「可回放、可审计、可复现」为产品前提的 harness 而言，这笔交易不成立；所以它把「修改当前语义」完整地放进**派生层与迁移层**，而不是放进**日志层**。

## 附录 A 关键问题与答案

> ✅ 四道题**全部给出明确答案**，不留空、不写「待补充」。**Q1 是第一次读就该能答的**；**Q2–Q4 涉及后续编才会展开的细节**（settlement 的字段级规则、迁移链每跳的准入集合、投影 seam），标题下已标「第一次读请跳过」，回查时再看。

### Q1 事件溯源的收益与代价各至少 3 条？

**收益**（完整 6 条见 §5.1，这里给最核心的 3 条）：

1. **状态与日志结构上不可能分歧**——替代方案被明确否决（2026-06-11 Note 第 21 行）。
2. **回放、追踪、遥测是结构保证，而非事后附加**（同 Note 第 25 行）。
3. **模型历史是纯函数**：每个请求都能从日志重建（`docs\architecture.zh.md` 第 131 行；`packages\core\session\README.zh.md` 第 119 行）。

**代价**（完整 6 条见 §5.2，这里给最核心的 3 条）：

1. **派生成本随日志长度增长**（2026-06-11 Note 第 28 行）——914 万事件 / 2.016GB retained heap 是量级侧证。
2. **存储只增不减**：已提交代际绝不改名、替换、删除（`docs\architecture.zh.md` 第 129 行）。
3. **事件基数是协议**：改基数要重映射全部引用，且原文承认这是**有意为之**（2026-09-01 Note 第 40、80 行）。

### Q2 如果允许改写历史，会失去什么？

**8 条逐项清单见 §5.3。**一句话版本：**失去的是「同一份日志在任何时刻都指向同一段事实」这个前提**，于是 fork 的切点、`request/header` 的重建、KV cache 前缀、迁移链的可证明性、源字节不变的验收断言、拒绝而不猜测的姿态、只读与写入的分离、以及所有下游指标的一致基准——**同时失效**。

> ⚠️ **第一次读请跳过本节剩余部分**：Q3、Q4 涉及 settlement 字段级规则与迁移链每跳的准入集合，属于 `4.3` 与 `4.5` 的内容。

### Q3 fork / 恢复 / transcript / 遥测为什么都能从持久 settlement 派生？

**因为它们要的是同一份事实，而这份事实恰好被设计成「每个 attempt 一个原子单位」。**

1. **共享的原子单位是 settlement。** 每个完成结算的模型尝试都提交一个事件：成功的 `assistant/message` 携带组装后的模型可见 message 及其紧凑带时间 stream，没有 surface 内容的 `assistant/attempt` 保留失败/重试/取消/stream error 且不加模型历史（`packages\core\session\README.zh.md` 第 88 行；2026-09-01 Note 第 19–22 行；字段见 §3.3）。原文直接把这条定性为「settlement 是原子 owner」，并否决了把 stream 放 sidecar 的方案——理由正是那会把一个 attempt 的 message 与证据拆给不同持久性 owner（同 Note 第 68 行）。
2. **fan-out 是同一份派生的四个读者，而不是四套日志。** `docs\architecture.zh.md` 第 127 行一句写全：fork、恢复、transcript、遥测与持久化都从这些持久 settlement 派生，实时 UI 增量则来自 `agent/assistant-stream`。四者的需求交集（顺序、时间、usage、content、replay state）全在 settlement 内。
3. **每个派生者只取自己要的字段，不必共享同一解析策略**（分工表见 §4.4）：fork 只切前缀（§3.7）；恢复只校验 runtime 直接依赖的字段；UI 结算后直接从 `assistant/message` 构造；遥测按 attempt 而非 token chunk 扩展；要逐 token 证据的才调 `expandAssistantStream()`。
4. **时间与顺序信息只在 settlement 里完整。** 同一 block 的连续 delta 折成一个 compact run，保留首个时间戳与精确间隔，每个原始 delta 对应一个数组成员；展开严格还原，**压缩从不合并 delta 边界**（2026-09-01 Note 第 24 行）。
5. **增量与历史共用一套投影。** surface 是派生投影、`deriveMessages()` 增量缓存（§3.5），host 消费方通过 `ctx.sessionProjections` 的 `stateOf()` / `snapshot()` 读类型化状态（`docs\architecture.zh.md` 第 133 行；`packages\core\session\README.zh.md` 第 88 行）→ 「实时看到的」与「重放得到的」走同一条折叠逻辑。
6. **唯一不能派生的东西，设计是明说的而不是遗漏的**：settlement 之前的 in-flight stream 有意只存在于进程内（2026-09-01 Note 第 74、76 行）。派生清单能覆盖四类读者，是因为它们都只消费**已结算事实**。

### Q4 迁移链为什么设计成「一个包负责一步」？

1. **相邻性是可执行契约，不是约定。** `defineSessionFormatMigration` 在声明处就检查 `to === from + 1`，违反即抛（`packages\session\session-format\src\chain.ts` 第 30–32 行，§3.8 ①）。跨版本「一步到位」在类型／装配层面**无法注册**。
2. **缺口在构建期暴露，而不是在用户打开旧会话时。** 构造函数遍历 `version < currentVersion` 的每一段，缺失即 `Session migration vN->vN+1 is missing`；越界的边也被拒（同文件第 65–75 行，§3.8 ④⑤）。目录在**模块初始化时**就校验完整、无缺口、无重复（`packages\session\session-format-catalog\README.zh.md` 第 12 行）。
3. **一跳一个大语义主题，各自拥有独立的准入与拒绝规则。** v0→v1 处理改名与确定性补 id；v1→v2 处理 attempt folding 与引用重写；v2→v3 有自己的投递保护；v3→v4 处理父目录补全（2026-08-31 Note 第 70–74、90–92 行）。原文明确：**历史内容准入归入边所有**，在不了解字段的情况下保留未知块不能证明迁移保留了其含义（第 76 行）。
4. **一步一包让「冻结的前代校验器」可以复用而不是复制。** V3→V4 复用 V2→V3 中冻结的 V3 codec；已发布 V2 codec 仍归 V1→V2 所有并被复用而非复制（第 70、74 行）。若把多跳塞进一个包，这些**所有权边界无法表达**。
5. **每跳有自己的状态与不变量。** v0→v1 要跟踪 message 与 retry identity；v1→v2 要暂存尚未结算的 attempt、被它阻塞的后续事件并维护 old-to-new seq 映射（第 24 行）。stage 拥有单一 artifact 的可变状态、不同 Session 之间绝不共享实例（第 28 行）；「全局复用有状态 codec instance」被列为明确否决的替代方案，因为它会让不同 Session 的 pending attempt、mapping 与 counter 相互污染（第 249 行）。
6. **引用重映射按跳归属，拒绝也按跳归属。** v1→v2 只重映射「有限的已声明引用清单」，并且**指向被消费 chunk 的引用会使迁移失败**、绝不重定向到含义不同的 settlement（2026-09-01 Note 第 40 行）。一步一包才能让「哪一跳拒绝、为什么拒绝」可定位。
7. **发布语义要求中间版本不落盘。** 迁移只写最终 current target，中间版本只存在于 stage state（2026-08-31 Note 第 114 行）。链式 stage 把中间态限制在一次 artifact 的内存生命周期内——这也解释了为什么链是「按源→目标顺序创建 stage、按反方向用 context 连接」（同 Note 第 54 行）。
8. **一条真实代价被写进后果**：Stage 架构删掉了完整 source 与中间 target array，但**最终 current-event array 仍然不可消除**，因为 Session restore 与 Agent 执行需要完整历史（第 234 行）。所以「一步一包」优化的是**内存与所有权**，不是总数据量。
